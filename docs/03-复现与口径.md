# 复现与判读口径

## 1. 环境

| 项 | 版本 / 说明 |
|---|---|
| apktool | 3.0.3（`JAVA_OPTS="-Xmx4g"`，8 线程，52MB APK 解包约 7 秒） |
| Java | OpenJDK（/usr/local/bin/java） |
| Python | 3.x（只用标准库：zipfile / xml.etree / difflib） |
| aapt | Android SDK build-tools（仅用于 badging，改版会报 arsc 越界） |
| apksigner | 仅用于签名校验 |
| 运行环境 | Debian chroot（Linux 环境），宿主目录映射 `/workspace` |

## 2. 一键复现

```bash
export JAVA_OPTS="-Xmx4g"
mkdir -p work && cd work

apktool d -f --no-debug-info -o A "/path/系统界面_17.03.260226.r.apk"
apktool d -f --no-debug-info -o B "/path/MiuiSystemUI.apk"

# 1) ZIP 条目层（不用解包，可直接对 APK 跑）
python3 scripts/zipdiff.py A.apk B.apk zip_layer.txt

# 2) 类级 md5 索引
python3 scripts/index_classes.py A B data
#   → new_classes.txt / del_classes.txt / differ_classes.txt

# 3) 方法级归一化 diff
DIFF_A=A DIFF_B=B DIFF_DATA=data python3 scripts/analyze_methods.py
#   → real_classes.txt / method_diff.tsv / real_diff.md

# 4) 资源集合对比
DIFF_A=A DIFF_B=B DIFF_DATA=data python3 scripts/vals_compare.py
#   → vals_diff.md / resfile_diff.md / res_diff_text/

# 5) 生成本仓库的两篇 docs
python3 scripts/gen_docs.py
```

## 3. 归一化规则（为什么必须做）

逐文件 md5 得出的 244 个「内容不同」类里，**只有 53 个是真的改了**。剩下 191 个（78.3%）是 dex 重编译产生的噪声。四条规则即可滤掉：

| 规则 | 处理 | 典型误报 |
|---|---|---|
| dex 对齐填充 | 丢弃 `nop` | 方法尾部多出 nop |
| 调试信息 | 丢弃 `.source` / `.line` / `.prologue` | go/retraceme 方法哈希、行号表全变 |
| 寄存器重编号 | `\b[vp]\d+\b` → `R` | 加一行代码导致后续寄存器整体平移 |
| 标签重命名 | `:[A-Za-z0-9_$-]+` → `:L` | `:cond_0` / `:goto_0` 编号变化 |
| 字符串池溢出 | `const-string/jumbo` → `const-string` | 跨 65535 引用阈值 |
| 字段静态初值 | 去掉行尾 `= null / = 0x0 / = false` | 反编译器的默认值表示差异 |

未纳入归一的（会保留为真实改动）：`.registers` / `.locals` 的数值本身不参与比较（整行丢弃），因此**单纯改寄存器数量的改动会被吞掉**——实际不影响语义，可接受。

## 4. 资源层为什么用集合对比

apktool 输出 XML 的属性顺序、缩进不稳定，直接 `diff -u` 两个 `values/` 目录会产生大量假增删。因此：

- values 层：解析成 `(variant, type, name) → (值, 属性集, 子元素列表)` 映射后比较。
- 颜色做 6/8 位归一化：`#RRGGBB` 与 `#ffRRGGBB` 视为同色。
- `format` / `translatable` 等展示性属性不参与比较。
- 文件资源层（layout / drawable / xml / raw）：按 `res/<type>-<variant>/<file>` 键比较文本，并先把 `>\s+<` 折叠成 `><` 消除缩进噪声。

结果：values 层 124 新增 / 20 删除 / 146 值变化；文件资源 34 新增 / 0 删除 / 33 变化。ZIP 层同口径为 38 新增 / 0 删除 / 37 变化——两边差异来自 `resources.arsc` 与 `AndroidManifest.xml`（ZIP 层算 1 个条目，解码态拆成上千个键）。

## 6. 已知误报源与盲区

1. **寄存器重编号已归一，但 `.locals` 变化被整行丢弃**：极端情况下「仅新增局部变量声明、无实际指令变化」不会报出。本包未出现此情况。
2. **`resources.arsc` 内部结构调整**（字符串池重排）在 values 层看不出，只能从文件大小与 `public.xml` 条目数判断。
3. **`5Gᴀ` 这类 Unicode 小体大写字符**按码点比较，视为与 `5GA` 不同（实际就是不同）。
4. **dex 内联优化差异**：`invoke` 被内联成直接字段访问时，方法清单会变但语义不变，本包未出现。
5. **签名只比对 `META-INF` 三件套**：v2/v3 签名块在 ZIP 结构里单独存放，若只动了 v3 块而 `META-INF` 未变，本方法会漏判。本包已用 `apksigner verify` 交叉验证（改版 v3 摘要不匹配，符合「未重签 + 内容已改」）。
